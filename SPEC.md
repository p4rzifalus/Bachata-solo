## Цель прототипа

Проверить одну гипотезу: **можно ли по камере телефона или ноутбука надёжно ловить шаги базового шага бачаты и измерять, насколько они попадают в музыкальный ритм.**

Красота интерфейса, аккаунты, распознавание элементов и библиотека треков сейчас не нужны. Нужен работающий цикл «камера → шаги → сравнение с битом → понятный результат» и инструменты отладки, чтобы подкрутить детекцию.

## Технические рамки

- Звук: Web Audio API.

- Должно работать в Chrome и Safari на iPhone, в вертикальной ориентации, и на ноутбуке.

## Музыка

В прототипе три источника. Для движка они одинаковые: у каждого есть аудио и файл разметки в едином формате (см. ниже). Движок про источник ничего не знает — он работает только с разметкой.

### 1. Встроенный бачата-метроном

Генерируется через Web Audio, поэтому время каждого удара известно точно. Это эталон для отладки детекции.

- Темп настраивается от 110 до 150 BPM, по умолчанию 128.  
- Звуки: гуира на каждый удар (короткий шумовой щелчок), бас на 1 и 5, акцентный звук (бонго или хлопок) на 4 и 8.  
- Отсчёт — 4 удара.  
- Разметка генерируется программно, в том же формате, что и у треков.

### 2. Каталог размеченных бачата-треков

Основной режим для реальной тренировки.

- Треки лежат в папке `tracks/`. Каталог — файл `tracks/catalog.json`: список треков с названием, исполнителем, темпом, сложностью (1–3), длительностью, путём к аудио и путём к разметке.  
- Разметка каждого трека — отдельный файл `tracks/<id>.json`.  
- **Права на музыку.** Сайт публичный (GitHub Pages), поэтому в репозиторий попадают только треки со свободной лицензией. Лицензию и источник пишем в каталоге. Коммерческие треки (Romeo Santos, Prince Royce и т. п.) в репозиторий **не** кладём, для них — режим «Мой трек с разметкой»:  
  - в каталоге есть разметка трека, но нет аудио;  
  - пользователь выбирает mp3 со своего устройства;  
  - сайт проверяет, что файл подходит: совпадение длительности ±1 сек. Если не совпадает — предупреждение «Похоже, это другая версия трека, разметка может не совпасть»;  
  - аудио не загружается на сервер и не сохраняется.  
- В `.gitignore` добавь папку `tracks/private/` для моих локальных аудиофайлов.

### 3. Свой mp3 без разметки (быстрый режим)

Пользователь загружает файл, вводит BPM (или тапает темп) и одним нажатием отмечает «раз». Дальше сетка считается равномерной. Качество ниже, это нормально. Отсюда должна быть кнопка «Открыть в редакторе разметки», чтобы разметить трек нормально.

### Формат разметки (единый для всех источников)

```json
{
  "id": "example-track",
  "title": "Название",
  "artist": "Исполнитель",
  "duration": 214.3,
  "bpm": 128,
  "beats": [0.512, 0.981, 1.450],
  "downbeats": [0.512, 4.262],
  "countStart": 0.512,
  "sections": [
    { "start": 0.512, "type": "intro" },
    { "start": 15.51, "type": "derecho" },
    { "start": 60.02, "type": "majao" },
    { "start": 105.4, "type": "mambo" }
  ],
  "accents": [
    { "time": 44.51, "type": "break", "duration": 1.9 },
    { "time": 88.02, "type": "hit" }
  ],
  "danceStart": 15.51,
  "verified": true,
  "license": "CC BY 4.0",
  "source": "https://..."
}
```

- `beats` — время каждого удара в секундах. Хранится полным списком, а не только BPM: живые треки немного плавают по темпу.  
- `downbeats` — «раз» каждой восьмёрки (не такта из 4!). Это главный ориентир для проверки «старта с раз».  
- `countStart` — первый «раз», от которого идёт счёт.  
- `sections` — части трека: intro, derecho, majao, mambo, break, outro.  
- `accents` — брейки (музыка останавливается), стопы и хиты (резкий общий акцент). В прототипе они только отображаются на таймлайне, в оценку не идут.  
- `danceStart` — откуда обычно начинают танцевать (после вступления). Сессия по умолчанию стартует отсюда.  
- `verified` — разметку проверил человек. Непроверенная разметка помечается в каталоге значком.

## Редактор разметки

Отдельная страница `editor.html`. Это мой рабочий инструмент: через него я размечаю треки для каталога.

1. **Загрузка.** Выбираю mp3 с устройства.  
2. **Автоматическая первичная разметка прямо в браузере.** Используй Essentia.js (определение темпа и ударов) или аналог — предложи, что лучше работает для латиноамериканской музыки. Результат — сетка ударов.  
3. **Экран редактора.**  
   - Волна трека (waveform), поверх — риски ударов. «Раз» выделен, части трека окрашены разным фоном.  
   - Масштаб и прокрутка. Воспроизведение с любого места, с бегущей линией и щелчком метронома поверх трека (вкл/выкл) — чтобы на слух проверить, что сетка совпадает.  
4. **Правка.**  
   - Сдвинуть всю сетку целиком влево/вправо (грубо и точно, шаг 5 мс).  
   - Сдвинуть отдельный удар; остальные после него пересчитываются, если выбрана опция «тянуть хвост».  
   - Кнопка «Здесь раз» — назначить выбранный удар первым в восьмёрке, остальные «раз» пересчитываются каждые 8 ударов.  
   - Тапать удары вручную по пробелу/экрану во время воспроизведения — как альтернатива автоматике. Итоговая сетка — усреднение тапов.  
   - Поставить начало части (intro/derecho/majao/mambo/break/outro).  
   - Поставить акцент (break с длительностью / hit) в текущей позиции.  
   - Отметить `danceStart`.  
5. **Проверка.** Кнопка «Прослушать с отсчётом»: трек играет, счёт 1–8 голосом или щелчками поверх. Галочка «Проверено» → `verified: true`.  
6. **Сохранение.** Скачать JSON разметки. Загрузить ранее сохранённый JSON вместе с аудио, чтобы продолжить.  
7. Необязательно, но полезно: кнопка «Скопировать запись для catalog.json».

Про «раз» отдельно: автоматика хорошо находит удары, но часто ошибается с тем, где «раз» в восьмёрке. Поэтому в редакторе «раз» всегда подтверждается вручную.

## Пользовательский сценарий

1. **Старт.** Короткое объяснение и кнопка «Включить камеру».  
2. **Проверка кадра.** Зеркальное видео, поверх него скелет.  
   - Если человек не целиком в кадре (у голеностопов, коленей и плеч низкая видимость) — подсказка: «Отойди дальше, нужны ступни в кадре».  
   - Кнопка «Дальше» активна только когда всё тело в кадре хотя бы 2 секунды.  
3. **Калибровка задержки** — один раз, результат сохраняется в localStorage.  
   - Звучит метроном, человек шагает на месте на каждый удар, 16 ударов.  
   - Первые 4 удара не считаются, по остальным берётся медиана опозданий. Это личная поправка: наушники + камера + реакция.  
   - Показать результат: «Твоя поправка: 180 мс».  
   - Кнопка «Перекалибровать» доступна всегда.  
   - Подсказка: «Если сменишь наушники — перекалибруйся».  
4. **Выбор музыки.** Три вкладки:  
   - «Треки» — каталог: карточка с названием, темпом, сложностью, отметкой «нужен свой файл» для треков без аудио;  
   - «Метроном» — слайдер темпа;  
   - «Свой mp3».  
5. **Танец.**  
   - Метроном: отсчёт, потом 60 секунд базового шага (1-2-3-тап, 5-6-7-тап). Длительность настраивается.  
   - Трек: старт с `danceStart`, голосовой или щелчковый отсчёт «5-6-7-8» перед первым «раз», дальше до конца трека или до кнопки «Стоп». Опция «только первая минута».  
6. **Результат** (см. ниже).

## Экран во время танца

- Зеркальное видео со скелетом, приглушённое.  
- Крупно — текущий счёт 1–8. На 1 он заметно выделен.  
- Каждый распознанный шаг даёт короткую цветную вспышку по краю экрана:  
  - зелёная — в пределах ±70 мс от удара,  
  - жёлтая — ±70–150 мс,  
  - красная — дальше.  
- Тап помечается отдельной иконкой.  
- Больше ничего: во время танца на экран почти не смотрят.

## Детекция шагов

Это ядро прототипа. Все пороги вынеси в один объект настроек и выведи слайдерами в отладочной панели, чтобы я мог подбирать их руками.

1. **Сглаживание.** Точки скелета дрожат, особенно голеностопы. Используй фильтр One Euro или аналог.  
2. **Нормализация.** Все расстояния считай в долях размера тела (например, расстояния плечи–бёдра), чтобы не зависеть от удалённости от камеры.  
3. **Событие «стопа встала»** — для каждой ноги отдельно. Стопа была заметно приподнята или двигалась, потом остановилась у пола. Время события — момент остановки, а не момент подъёма.  
4. **Шаг или тап.**  
   - Шаг: после постановки центр бёдер сместился к этой ноге, то есть вес перенесён.  
   - Тап: касание без переноса веса.  
5. **Защита от дублей.** Минимальный интервал между событиями одной ноги — примерно 60% длительности удара.  
6. Каждое событие сохраняется: время (по аудио-часам, с учётом поправки калибровки), нога, тип (шаг/тап), уверенность.

## Сопоставление с музыкой и метрики

Каждое событие привязывается к ближайшему удару. Получаем опоздание в мс (минус — раньше, плюс — позже) и номер счёта 1–8.

Метрики сессии:

| Метрика | Как считается | Как показать человеку |
| :---- | :---- | :---- |
| Среднее смещение | среднее опозданий | «В среднем ты на 60 мс раньше бита» |
| Стабильность | стандартное отклонение опозданий | «Стабильно» / «Плаваешь» + число |
| Попадание | % событий в ±70 мс и в ±150 мс | два процента |
| Темп | медианный интервал между шагами ÷ длительность удара | «В темпе» / «Медленнее в 2 раза» / «Торопишься» |
| Старт с раз | на какой счёт пришёлся первый шаг | «Начал с 1 ✓» или «Начал с 3 — вход должен быть на раз» |
| Тапы на 4 и 8 | % тапов, попавших на 4/8; тапы на других счетах тоже считаются | «Тапы на месте в 85% восьмёрок» |

## Экран результата

- Крупная итоговая оценка 0–100. Формулу предложи сам и объясни.  
- Метрики из таблицы — человеческими фразами.  
- **Таймлайн:** горизонтальная полоса по всей сессии. Удары — тонкие риски, «раз» — толще. События — точки над или под линией: насколько раньше или позже. Цвет как во время танца.  
- Для треков: на таймлайне цветом показаны части трека (derecho/majao/mambo), значками — брейки. Метрики дополнительно разбиты по частям: «В derecho — 92%, в mambo — 61%». Быстрые части обычно даются хуже, и это полезно видеть.  
- Кнопки «Ещё раз» и «Скачать данные сессии (JSON)».

## Отладочный режим

Включается по `?debug` в адресе. Без него я не смогу подкрутить детекцию, поэтому это обязательная часть.

- Живой график за последние 5 секунд: высота обоих голеностопов и горизонтальная позиция центра бёдер. Вертикальные линии — удары, отметки — распознанные события.  
- Панель слайдеров со всеми порогами детекции.  
- FPS камеры и модели.  
- Экспорт сырых данных сессии: координаты по кадрам + события + удары. Это позволит потом прогонять детекцию на записях без повторного танца.

## Что НЕ делаем сейчас

- Распознавание элементов (повороты, волны, хип-роллы).  
- Оценка попадания в акценты и брейки. Разметка их уже содержит, на таймлайне они видны, но в метрики пока не идут.  
- Запись видео и повтор со скелетом.  
- Аккаунты, сервер, история, геймификация.  
- Красивый дизайн — только аккуратный минимальный интерфейс. Дизайн я сделаю сам позже.

## Порядок работы

Останавливайся после каждого этапа.

1. **Каркас.** Страница, камера, зеркальное видео, скелет, проверка «всё тело в кадре». Выложено на GitHub Pages, можно открыть с телефона.  
2. **Метроном.** Генерация бачата-бита, счёт 1–8 на экране, отсчёт. Проверка: звук ровный, без плавания темпа, счёт на экране совпадает со звуком.  
3. **Детекция шагов + отладочный режим.** Графики, события, слайдеры. На этом этапе я танцую и настраиваю пороги вместе с тобой.  
4. **Калибровка задержки.**  
5. **Сессия танца + метрики + экран результата** — пока на метрономе.  
6. **Формат разметки и воспроизведение трека по разметке.** Загрузить трек и готовый JSON (для теста разметь одну восьмёрку вручную), счёт 1–8 на экране идёт синхронно с музыкой, сессия и метрики работают на треке.  
7. **Редактор разметки** (`editor.html`): волна, автоматическая разметка, ручная правка, «здесь раз», части, акценты, проверка на слух, экспорт.  
8. **Каталог треков**: `catalog.json`, экран выбора, режим «Мой трек с разметкой» с проверкой длительности, быстрый режим «Свой mp3».

После этапа 7 я размечу 3–5 треков разного темпа, и мы проверим на них весь цикл.

## Критерии приёмки

- На iPhone в Safari и на ноутбуке в Chrome стабильно работает ≥20 FPS модели.  
- При медленном, чётком базовом шаге на 120 BPM, при хорошем свете и с телом целиком в кадре, распознаётся ≥90% шагов, а ложных срабатываний не больше 1 на восьмёрку.  
- Если я специально танцую с опозданием примерно на пол-удара, сервис это показывает.  
- Если я начинаю с 3 вместо 1, сервис это ловит.  
- После калибровки при попадании «на слух» среднее смещение укладывается в ±50 мс.  
- Всё работает без интернета после первой загрузки модели — не обязательно, но желательно.  
- Разметка трека: при воспроизведении с включённым метрономом щелчки на слух совпадают с музыкой на всём треке, без накопления расхождения к концу.  
- В редакторе трек средней длины (3–4 мин) размечается и проверяется за 10–15 минут.  
- Одна и та же разметка даёт одинаковый счёт на экране танца и в редакторе.
